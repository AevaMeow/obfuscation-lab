# Лабораторная работа по обфускации

## Идея

Обфускация методом виртуализации: логика проверки ключа переносится из
обычного машинного кода в байткод собственной виртуальной машины.

В `crackme_vm.c` проверка ключа записана как программа для кастомной
стековой VM. В ELF встроены интерпретатор VM и зашифрованный байткод:
процессор выполняет интерпретатор, а интерпретатор - инструкции VM.

Правильный ключ имеет формат `XXXX-XXXX-XXXX-XXXX`: длина 19 символов,
дефисы на позициях 4, 9 и 14.

## Структура проекта

| Путь | Назначение |
|---|---|
| `vm/crackme_vm.c` | исходник обфусцированного crackme с VM |
| `bin/crackme_ida` | собранный stripped-бинарь для реверса |
| `generator/bytecode_generator.c` | генерация байткода по ключу |
| `solver/solver.py` | решатель ключа на Python + Z3 |

## Методы обфускации

- **Шифрование строк.** Сообщения `Correct`, `Wrong`, `Usage` хранятся
  зашифрованными; `print_encrypted_message` расшифровывает их при выводе.
- **Усложнённые константы.** Длина и позиции дефисов заданы выражениями,
  например `19 = (3 * 7) - 2`. Есть константа от ввода:
  `volatile int zero = input[0] ^ input[0]`.
- **Opaque predicate.** Выражение `(x * x + x) & 1` всегда чётное, значит
  всегда `0`. Для анализатора выглядит как реальное условие, но проверка
  всегда уходит в VM.
- **Ложные ветки.** `fake_key_check` считает правдоподобный хеш, но лежит
  на недостижимом пути за opaque predicate.
- **Control-flow flattening.** `check_key` и `check_key_format_flattened`
  написаны как цикл со `switch` и переменной `state` - вместо цепочки
  `if` декомпилятор показывает автомат состояний.
- **Виртуализация.** Проверка каждого символа записана инструкциями VM;
  их исполняет `execute_vm`.
- **Шифрование байткода.** Массив `encrypted_vm_bytecode` хранится
  зашифрованным (см. ниже).
- **Strip.** После сборки `strip --strip-all` убирает имена функций - в
  IDA они становятся `sub_4012E1`, переменные `var_...`.

## Виртуальная машина

Кастомная стековая VM. Стек - массив `stack[256]`, опкод занимает 1 байт.

| Opcode | Имя | Описание |
|---|---|---|
| `0xA7` | `LOAD_CHAR i` | кладёт `input[i]` на стек |
| `0x3D` | `PUSH_CONST v` | кладёт константу на стек |
| `0xE1` | `XOR` | снимает два значения, кладёт их XOR |
| `0x64` | `CMP_EQ` | сравнивает два значения, кладёт `0`/`1` |
| `0x9B` | `AND` | логическое AND двух результатов |
| `0x2C` | `RET` | возвращает верх стека |
| `0xD1` | `JUNK v` | меняет фиктивное состояние, на ключ не влияет |
| `0x6D` | `DEAD o` | ложный переход через opaque predicate |

Длина инструкции:

- 1 байт: `XOR`, `CMP_EQ`, `AND`, `RET`;
- 2 байта (опкод + операнд): `LOAD_CHAR`, `PUSH_CONST`, `JUNK`, `DEAD`.

## Проверка ключа

Символ сравнивается не с открытым ASCII, а в замаскированном виде:

```text
(input[i] XOR mask) == encoded        encoded = correct_char XOR mask
```

Байткод одной позиции:

```text
LOAD_CHAR i
PUSH_CONST mask
XOR
JUNK value
PUSH_CONST encoded
CMP_EQ
```

Результаты всех 19 сравнений объединяются через `AND`, а `RET` вернёт
`1` только если совпали все. Пример для первого символа:

```text
input[0] XOR 0x6D == 0x26   ->   input[0] = 0x26 XOR 0x6D = 0x4B = 'K'
```

Байткод хранится зашифрованным. Байт в позиции `i` расшифровывается так:

```c
decoded = encrypted[i] ^ (((i * 17) + 0x5A) ^ 0xA5);
```

## Поток выполнения

1. `main` берёт ключ из `argv[1]`.
2. `check_key` запускает flattened-автомат и проверяет формат ключа.
3. `opaque_predicate` всегда направляет выполнение в VM.
4. `execute_vm` читает байты через `vm_fetch_byte` (с расшифровкой) и
   исполняет опкоды, формируя на стеке 19 результатов сравнений.
5. `AND` сводит их в один, `RET` возвращает итог.
6. `main` выводит `Correct` или `Wrong`.

## Решатель (Z3)

`solver/solver.py` восстанавливает ключ из байткода. Сначала ключ
реверсят вручную (длина, опкоды, формула сравнения), затем передают
байткод решателю как hex-строку без пробелов.

Что делает решатель:

1. Переводит hex в байты и расшифровывает их позиционным потоком.
2. Заводит 19 неизвестных байтов ключа: `key_00 … key_18`.
3. Символически исполняет VM: `LOAD_CHAR` кладёт переменную ключа,
   `PUSH_CONST` — константу, а `XOR`, `CMP_EQ`, `AND` строят выражения Z3.
4. Условие с вершины стека при `RET` добавляет в решатель.
5. Если результат `sat`, из модели читает значения и собирает ключ.

Используемый API Z3: `BitVec`/`BitVecVal` (символы и константы),
операторы `^` и `==`, `And`, `Solver`, `solver.add/check/model`,
`model[var].as_long`. Hex разбирается через `bytes.fromhex`.

## Генератор байткода

`generator/bytecode_generator.c` собирает `encrypted_vm_bytecode` по
произвольному ключу и печатает готовый C-массив:

```bash
./generator/bytecode_generator K1R1-0BF5-VM42-C0DE
```

Для каждого символа `i` он считает `mask = (0x6D + 29*i) & 0xFF` и
`encoded = key[i] XOR mask`, выдаёт инструкции
`JUNK / [DEAD] / LOAD_CHAR / PUSH_CONST mask / XOR / JUNK /
PUSH_CONST encoded / CMP_EQ / [AND]`, завершает их `RET` и шифрует весь
массив позиционным потоком. Для `K1R1-0BF5-VM42-C0DE` результат совпадает
с байткодом (259 байтов), зашитым в `crackme_vm.c`.

## Сборка

```bash
pip install z3-solver        # для solver.py
sudo apt install build-essential   # gcc для crackme и генератора
make
```

## Запуск

Crackme:

```bash
./bin/crackme_ida K1R1-0BF5-VM42-C0DE
```

Solver - передать байткод одной hex-строкой без пробелов:

```bash
python3 solver/solver.py 2EFE7E28066784A5...
```
